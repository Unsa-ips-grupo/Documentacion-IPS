Scrum y DevOps aplicado a un sistema hospitalario en producción real

Tomamos Danphe EMR, un sistema de información hospitalaria de código abierto utilizado en más de 60 hospitales de Asia y África, y le aplicamos un proceso riguroso de Scrum integrado con prácticas DevOps. Lo que entregamos al curso es ese proceso, documentado y verificable.

Módulos Estructurales

Análisis de las funcionalidades principales sobre las que ejecutaremos nuestras iteraciones Scrum.

🏥 Admisión y Registro (ADT)

Gestión completa del ciclo de vida del ingreso hospitalario. Incluye el registro inicial de pacientes ambulatorios, asignación y transferencia de camas para pacientes internados, y el flujo de alta médica.

💊 Farmacia y Dispensario

Módulo de control de inventario médico (SCM). Maneja alertas automáticas por caducidad de medicamentos, control de lotes, dispensación conectada a las recetas de los doctores y control de devoluciones.

👨‍⚕️ Gestión Clínico/Médica

El núcleo operativo para el personal de salud. Permite a doctores y enfermeras registrar signos vitales, redactar notas de evolución, generar prescripciones electrónicas y solicitar pruebas diagnósticas.

🧪 Laboratorio y Radiología

Recepción de muestras y digitalización de resultados. El sistema permite crear plantillas personalizadas para diferentes tipos de análisis y se integra directamente con el estado de cuenta del paciente.

💵 Facturación Integrada

Centraliza los cobros generados por farmacia, consultas, laboratorio y uso de cama. Gestiona depósitos, coberturas de seguros de salud y emisión de comprobantes fiscales automatizados.

Producto final del curso

Lo que entregamos al cierre del semestre

El producto que evaluamos no es Danphe en sí mismo, sino la aplicación rigurosa de Scrum y DevOps sobre él. A continuación los seis entregables tangibles que componen ese producto final.

01

Fork con mejoras del equipo

Repositorio fork en la organización Unsa-ips-grupo con funcionalidades nuevas implementadas vía pull requests, siguiendo flujo Git profesional con protección de rama main.

02

Containerización con Docker

Dockerfile + docker-compose.yml que orquestan ASP.NET Core, SQL Server y el frontend Angular en un solo comando. Mejora estrella del proyecto, no existía oficialmente.

03

Pipeline CI/CD en GitHub Actions

Workflows YAML que ejecutan tests xUnit, validan estilo de código .NET, construyen imágenes Docker y verifican que la aplicación arranca en cada push o pull request.

04

Despliegue automatizado a staging

Sistema desplegado en cloud (Railway, Render o VPS) actualizándose automáticamente con cada merge a la rama main. Demostración pública del Continuous Deployment.

05

Documentación Scrum completa

Actas de Sprint Planning, Reviews, Retrospectivas y backlog del producto. Todo trazable en el repositorio de documentación, demostrando aplicación real del marco ágil.

06

Artículo IEEE y demo final

Artículo académico siguiendo plantilla IEEE que documenta el proceso completo, decisiones técnicas, resultados y conclusiones. Más demostración en vivo del sistema funcionando.

Cronograma

Cuatro sprints, tres hitos

Cada sprint dura quince días calendario. El liderazgo del equipo rota por sprint conforme a la metodología establecida en el curso.

Sprint 0 · Planificación
22 abril — 13 mayo
Completado · Hito 1

Selección del producto, definición de roles, configuración del repositorio organizacional, tablero GitHub Projects y publicación de GitHub Pages. Cierre con la entrega del Hito 1, valorado en quince por ciento del trabajo final.

Sprint 1 · Setup técnico
14 mayo — 27 mayo
En curso

Levantar Danphe EMR en local, analizar su arquitectura modular, definir el backlog del producto y diseñar el primer borrador de la containerización con Docker. Documentación técnica completa de requisitos y arquitectura.

Sprint 2 · CI/CD básico
28 mayo — 10 junio
Pendiente · Hito 2

Pipeline funcional de GitHub Actions con ejecución de pruebas xUnit, validaciones de estilo y construcción de imagen Docker. Cierre con la entrega del Hito 2, valorado en sesenta por ciento del trabajo final.

Sprint 3 · Mejora funcional
11 junio — 24 junio
Pendiente

Implementación de mejora funcional sobre un módulo seleccionado y despliegue automatizado al entorno de staging. Containerización completa funcional con docker-compose.yml.

Sprint 4 · Cierre y artículo IEEE
25 junio — 8 julio
Pendiente · Hito 3

Redacción del artículo en formato IEEE, pulido de documentación, preparación de la demostración final. Entrega del Hito 3 el 13 de julio, valorado al cien por ciento del trabajo final.
